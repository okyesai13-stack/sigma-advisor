# Project Architecture Rules

- Keep business logic inside existing page/context modules while shared visual language lives in semantic CSS tokens and reusable UI primitives, so redesigns cannot alter the Supabase workflows.
- Store whiteboard section positions, dimensions, removed-section keys and connections alongside notes in lean_canvas boxes.__board; use shared geometry helpers so resizing, movement, membership and mapping stay consistent without changing agent workflows. Single-section deletion removes contained notes, while bulk deletion clears all board notes with an undo snapshot; both retain analysis results and tasks. Recreation restores saved section geometry.
- AI credit balances change only through database security-definer functions (spend_credits/refresh_credits); AI edge functions charge via _shared/credits.ts before calling the model, so the browser cannot skip or alter charges.
- Startup roadmaps live in their own startup_roadmap table (one row per business), generated by the startup-roadmap edge function and edited client-side, so whiteboard saves to lean_canvas cannot overwrite them.

- Execution workspaces use ProjectEngineContext and relational projects/tasks with membership RLS, version-checked task writes and trigger-generated activity; legacy analyses remain in WorkspaceContext so execution edits never overwrite whiteboard JSON or agent results.
- Use the existing whiteboard and roadmap editors only for legacy board tasks and milestones; relational execution tasks use dedicated project editors and completed-task-only progress.
- Paginate Supabase execution reads in stable 500-row batches and list rendering in 25-row pages to avoid silent default query truncation; future large-workspace search should move to server query filters.
- Use dnd-kit sensors for Kanban movement with optimistic version-checked persistence and rollback; never store board status only in browser state.
- Preserve the strategy dossier at /analysis and support legacy /dashboard#section-* links while /dashboard displays the project overview; synchronize route project IDs into the business context so advisor queries use the opened project.
- Use SidebarProvider for navigation and contextual links to the single Planz AI conversation screen; main workspace width is never permanently reserved for AI and duplicate chat mounts are prohibited.
- Relational planning uses milestones, milestone_tasks and task_dependencies in the execution context; all links are required, tasks may belong to multiple milestones in the same project, and progress is calculated rather than stored to stay current after task changes.
- Milestone editing and link replacement run in one authorized save_milestone transaction with version checks; only workspace owners/admins may override incomplete linked tasks with a recorded reason.
- Finish-to-Start is the active dependency type; backend project-locked cycle validation rejects invalid graphs, while date conflicts require explicit browser confirmation and never auto-reschedule successors.
- Calendar dates and timeline geometry use local date-only arithmetic; timeline pages contain at most 100 task rows and date writes retain task version checks and activity history.
- Dashboard/report counts use the security-invoker workspace_analytics RPC with membership checks and RLS; these routes do not preload every task. Activity cohorts use UTC dates, schedule deadlines use local date-only today, and current project progress uses all existing tasks.
- Task completion timestamps are trigger-owned, cleared on reopening and backfilled only from recorded completion events; missing historical timestamps never become invented trends.
- Report exports page authorized filtered records in batches of 500, escape CSV formulas and HTML, and generate PDFs locally without privileged credentials.
- Collaboration reuses workspace roles and composite project/task membership checks; public invoker RPC wrappers call non-exposed collaboration_private implementations so privileged invitation/file transitions remain server-authorized.
- Invitation secrets are hashed in membership records, expire after seven days and require explicit matching confirmed-email acceptance; raw links exist only in the server email outbox and immediate creator response.
- Files use private workspace-files storage with server-reserved immutable paths, metadata matching and two-step authorized deletion; comments store validated member UUID mentions and server-generated deduplicated notification events.
- Notification subscriptions are user-scoped and cleaned up; deadline reminders run hourly in Postgres with recipient timezone/preferences and event keys, independent of browser sessions.
- Email delivery stays pending until provider configuration exists; the authenticated manager-only collaboration-email endpoint uses provider idempotency keys and never exposes outbox or credentials to clients.
- Planz AI uses private route-addressed conversations and a server orchestrator with typed adapters around existing AI functions; execution project and owner-only business context stay distinct so workspace membership cannot expose another user's dossier.
- AI requests use conversation locks; specialists claim one-use paid runs (full/single) server-side, while other self-charging adapters retain their debits so caller-side charges cannot bypass or duplicate billing.
- Project intelligence computes measured evidence from complete authorized project reads before bounded model interpretation; missing baselines, capacity and skills remain unknown rather than inferred.
- Consequential AI changes require immutable scoped proposals and transactional authorized execution receipts; approvals execute the saved plan without reclassification, and task edits retain version checks.

- Public product previews are labelled illustrations, never live metrics; guided brief steps retain the existing save contract so presentation cannot change analysis inputs.
